# Codex 開発指示書 — Winmail Extractor

> 最初にこの文書を読み、実装からビルド、テスト、配布用 publish まで進めてください。質問せずに進められる範囲は合理的に判断し、完了時に実装状況と未確認事項を報告してください。

## 1. 目的と完成像

Windows の業務メールに添付される `winmail.dat`（Microsoft TNEF形式）から、内部の添付ファイルを**ネットワークを使わず**安全に抽出する、個人利用向けの小型デスクトップアプリを作る。

- **製品名（仮）:** Winmail Extractor
- **対象OS:** Windows 11 x64。Windows 10 x64でも動けば望ましいが、Windows 11を優先する。
- **技術:** C# / .NET 10 / WPF。UIは日本語。文字はメイリオまたは Yu Gothic UI を基本とする。
- **配布:** インストーラー不要のポータブル版。原則として `WinmailExtractor.exe` の単一ファイルで動作する self-contained publish。
- **起動:** EXEを直接開く／`winmail.dat`をドラッグ＆ドロップ／ファイル右クリックから「Winmail Extractorで開く」。
- **範囲:** 今回は個人PC用のMVP。Outlook/Gmailへの直接接続、PWA化、クラウド送信、更新確認、テレメトリーは実装しない。

**優先順位:** ①正確で安全な展開 ②確実な右クリック起動・登録解除 ③洗練されたUI ④ポータブル配布。機能を増やして完成を遅らせない。

## 2. 必須のユーザー操作

1. EXEを起動すると、端正なウィンドウが開く。大きなドロップ領域と「ファイルを選択」ボタンを表示。
2. `winmail.dat` を指定するとローカルで解析し、**保存はまだ行わず**抽出候補を一覧表示する。
3. ファイル名、拡張子または種類、サイズ、選択状態を表示。全選択・選択解除が可能。
4. 「選択したファイルを保存」を押すとフォルダー選択ダイアログが開く。保存後、「保存先を開く」を提供。
5. 不正なTNEF、空のTNEF、破損データなどは、クラッシュさせず自然な日本語で説明する。
6. 右クリック連携は設定画面から「登録」「解除」を実行できる。現在の登録状態も表示。
7. 登録後は `.dat` ファイルから右クリック→「Winmail Extractorで開く」でパス付き起動する（拡張子 `.dat` に限定し、`.dat` の既定アプリを奪わない）。Windows 11では **「その他のオプションを確認」側に表示される方式で可**。新しい標準コンテキストメニューへの直接表示は今回の必須要件にしない。

## 3. UI/UX方針（重要）

現代的で上質なデスクトップユーティリティを目指す。古いWindows Forms風の見た目、過度なグラデーション、大きすぎるアイコン、情報過多の画面は避ける。

### ビジュアルデザイン

- 余白を十分に取ったミニマルなレイアウト。ウィンドウの初期サイズは約 900×620、最小約 720×500（DPIに合わせて調整）。
- オフホワイトまたは淡いニュートラル背景、白いカード、深いグレーの本文、落ち着いたブルー/ティールのアクセント。色はリソース化する。
- 角丸（8〜14px）、控えめな境界線と影、穏やかなホバー／フォーカス表現。派手すぎない。
- アイコンは統一されたベクター表現（SVGの無断貼り付けではなく、ライセンス確認済みのリソースまたは自作ジオメトリ）。絵文字を主要アイコンに使わない。
- タイトル、補足、操作ボタン、状態メッセージのタイポグラフィ階層を明確にする。
- Windows 11らしい上品さを目指すが、Windows標準ダイアログは用途に応じて活用。
- 初期はライトテーマで十分。OSダークモード自動追従は余力があれば。ライトテーマの品質を犠牲にしない。
- キーボード操作、Tab移動、表示倍率125〜200%、長い日本語ファイル名を考慮する。

### 画面構成

- **ヘッダー:** 小さなアイコン + `Winmail Extractor` + 「端末内で安全に展開」程度の短い補足。右上に設定アイコン。
- **未読み込み:** 中央に点線または薄い枠のドロップゾーン、「winmail.dat をドロップ」「またはファイルを選択」。下部に「ファイルは外部へ送信されません」。
- **読み込み後:** 読み込んだファイル名と件数、添付ファイル一覧（チェックボックス/アイコン/ファイル名/サイズ）、下部に保存ボタン。
- **設定:** 右クリックメニュー連携「登録／解除」、登録先EXEのパス表示、Windows 11での表示位置の説明。
- **状態通知:** 読み込み中表示、成功・失敗のインラインメッセージ。不要なMessageBox連発は避ける。

**UIの完成を優先するために外部テーマライブラリを導入してもよいが、依存関係、ライセンス、単一EXE配布への影響を検証すること。** WPF標準コントロールをスタイル化する方式でもよい。画面だけを美しく作って抽出処理が動かない状態で完了扱いにしないこと。

## 4. 技術設計

### プロジェクト構成例

```text
WinmailExtractor/
  WinmailExtractor.sln
  src/WinmailExtractor/
    App.xaml / App.xaml.cs
    MainWindow.xaml / MainWindow.xaml.cs
    Views/SettingsWindow.xaml
    ViewModels/MainViewModel.cs
    Services/TnefExtractionService.cs
    Services/ContextMenuRegistrationService.cs
    Services/AttachmentSaveService.cs
    Models/ExtractedAttachment.cs
    Styles/Colors.xaml / Controls.xaml
  tests/WinmailExtractor.Tests/
  README.md
  publish.ps1
```

小規模なため過剰なレイヤーや複雑なDIフレームワークは不要。**UI・展開・ファイル保存・レジストリ操作の責務を分ける**。MVVMでまとめることを推奨。C#の可読性を優先し、業務的に意味のない過剰な抽象化はしない。LINQに依存した書き方は避け、素直なループでも構わない。

### TNEF解析

- 第一候補: OSS **MimeKit** の `MimeKit.Tnef`。`TnefPart.ExtractAttachments()` などの公開APIを利用。
- **注意:** `winmail.dat` は「メール全体のMIMEメッセージ」ではなくTNEF本体だけの場合がある。単純に `.eml` としてパースする前提にしない。MimeKit最新版の実際のAPIを確認し、TNEF本体から添付を取り出せる実装を行う。
- `ExtractAttachments()` が返す `MimeEntity` の型の違い（`MimePart`、`MessagePart` など）に注意し、少なくとも通常のファイル添付を適切に扱う。未対応の種類は理由を示す。
- 添付ファイル名の文字コード・日本語名・重複名・ファイル名なしを想定する。
- **ライブラリの仕様を推測で決めない。** API、サンプル、ライセンスを確認し、実際のTNEFサンプルで動作検証する。ライブラリに脆弱性の警告があれば解消する。

### 安全性・プライバシー

- ネットワークアクセス、アップロード、解析ログへの添付内容の記録は禁止。起動時のオンライン確認も不要。
- TNEFは不審な入力である可能性がある。例外処理、読み込みサイズ上限（初期値50MiBなど設定可能な定数）、添付件数上限、合計展開サイズ上限を設ける。
- 大容量データを無制限にメモリ保持しない。MVPでは合理的な上限を設け、超過時は親切なエラーを出す。
- 展開先パスの作成では **パストラバーサル対策** が必須。`../`、`..\`、絶対パス、ドライブ名、UNC、制御文字、不正文字、Windows予約名、末尾のドット/空白、空名を安全に処理し、選択された保存先ディレクトリの外へ書き込まない。
- 同名の添付ファイル、および保存先に既存のファイルがある場合、勝手に上書きしない。例: `document (2).pdf`。衝突判定とファイル作成は可能な限り原子的に行う（`CreateNew` 等）。
- 実行形式やスクリプトを抽出しても **自動実行・自動プレビューしない**。危険な拡張子は注意表示する。ファイル名の拡張子を根拠に安全だと断定しない。
- 本体を削除・変更しない。原則として作業ファイルを作らずメモリ上で解析し、必要なら一時ファイルの安全な削除を実装する。
- ファイルの内容や経路を勝手に外部送信しないことを README に明記。

## 5. 右クリックメニュー登録・解除（必須）

**管理者権限を必要とせず現在のWindowsユーザーのみに登録**する。管理者昇格やHKLMへの書き込みはしない。

想定例（実際の登録場所はWindows仕様を検証すること）:

```text
HKEY_CURRENT_USER\Software\Classes\SystemFileAssociations\.dat\shell\WinmailExtractor
  (Default) = Winmail Extractorで開く
  Icon      = "C:\path\to\WinmailExtractor.exe"
  command\(Default) = "C:\path\to\WinmailExtractor.exe" "%1"
```

- 上記は方針例。Windows 11の実環境で動作する適切なレジストリキーを検証する。
- `.dat`の既定の関連付け、他アプリの項目、ほかの登録情報を変更・削除しない。
- 画面のボタンから明示的に登録／解除。**初回起動時に黙って登録しない。**
- 登録時に実行ファイルの**絶対パスを安全に引用符付きで記録**。特殊文字、空白、日本語を含むパスを扱う。
- 登録済みかどうかを検出し、実行ファイルを移動した場合は「再登録が必要」と案内。登録解除では自分のキーだけを対象にする。
- 必要に応じて `SHChangeNotify(SHCNE_ASSOCCHANGED, ...)` を呼び、反映を通知。
- ユーザーがEXEを移動・削除するとメニューが古いパスを指すため、READMEと設定画面で注意喚起。
- Windows 11の新しい右クリックメニューに直表示されない場合は、**「その他のオプションを確認」から選ぶ**と説明する。モダンな上位メニュー統合（MSIX/COM等）はMVP対象外。
- コマンドライン引数で受け取ったファイルを、存在確認・拡張子に依存しない内容確認をした上で読み込む。引数なしでは通常画面を表示。

## 6. ポータブル配布

- Windows x64向け `dotnet publish` により self-contained / single-file EXEを生成。
- .NETランタイムの別途インストールを前提としない。
- `PublishSingleFile=true`、`SelfContained=true`、`RuntimeIdentifier=win-x64` を基本とする。必要なら `IncludeNativeLibrariesForSelfExtract=true` を検証。
- **WPFでのTrimは安易に有効にしない**。`PublishTrimmed=false` を基本とする。
- 実際に生成されたpublishフォルダーを確認し、配布ファイルが単一EXEとして動作するかテストする。生成物に別ファイルが必要なら理由を記録し、無理に「単一」と主張しない。
- EXEは任意フォルダーに配置でき、保存先以外への恒久的なデータ書き込みを極力しない。OS/.NETの一時展開が発生する場合はREADMEで説明。
- セキュリティ警告（SmartScreen等）を回避するための危険な設定変更や署名検証の無効化は案内しない。
- `publish.ps1` を追加し、誰でも同じビルドを再現できるようにする。

## 7. エラーとエッジケース

最低限、以下を扱う。

1. 正常なTNEFにPDF/Word/Excelなどが複数含まれる
2. 添付ゼロ、または通常の添付として取り出せない内容しかない
3. TNEFではない `sample.dat` を選択
4. 破損した／途中で切れたTNEF
5. 日本語、空白、長いファイル名
6. TNEF内部で同じ名前が重複
7. `..\evil.exe`、絶対パス、Windows予約名など悪意あるファイル名
8. 保存先に同名ファイルが存在
9. 読み込み・書き込み権限がない／ファイルが使用中
10. 入力が許容サイズを超過
11. 右クリックから起動、引数が不正、登録と解除、EXE移動後の状態
12. Windowsの125%・150%表示倍率での表示崩れ

### テストの原則

- 解析と保存ロジックはUIとは独立して自動テスト可能にする。
- 正常なTNEFサンプルを含むテストを用意する。公開・再配布可能なテストデータを利用するか、テスト用に合成する。**実際の業務メールをリポジトリにコミットしない。**
- 実ファイルで未確認の機能を「動作確認済み」と報告しない。
- レジストリ変更のテストは実際のユーザー環境に影響するので、明示的な手動テスト手順と復旧手順を文書化。

以下を満たしたときMVP完成とする。

- [ ] `dotnet build` 成功（可能なら警告なし）
- [ ] 単体テストが成功
- [ ] 正常な `winmail.dat` から添付が展開でき、元ファイルとのバイト一致を確認
- [ ] 破損・不正ファイルでアプリが落ちない
- [ ] 長い名前、日本語名、重複名、危険なファイル名でも安全に保存できる
- [ ] ドロップ、選択、一覧、選択保存、保存先を開くが使える
- [ ] 設定画面からユーザー単位の右クリック登録・解除が可能
- [ ] Windows 11の右クリック（必要なら「その他のオプションを確認」）から引数付きで起動できる
- [ ] 現代的な外観で、DPI拡大・キーボード操作に著しい問題がない
- [ ] Release / win-x64 / self-contained / single-file publish が完了
- [ ] `README.md` に使い方、右クリック登録・解除、EXE移動時の注意、安全性、ライセンスを記載

## 9. Codexへの進行指示

1. 作業ディレクトリの既存ファイルを確認。既存のユーザー成果物を無断削除しない。
2. MimeKitとWPFの実際のAPI、TNEFの取り扱い、ライセンス、右クリック登録方式を確認。
3. シンプルなデザイン方針を決めてからUIとロジックを実装。サンプル画面だけで止めない。
4. 解析→保存→右クリック連携→UI仕上げの順に、テストとビルドを挟んで進める。
5. 自動テスト、可能ならWindows実機での手動テストを実施。実施できないテストは「未実施」と明示。
6. ポータブルEXEをpublishし、`README.md`、`publish.ps1`、検証結果を揃える。
7. 最終報告に **作成ファイル一覧／使い方／ビルド・publishコマンド／テスト結果／残課題／手動確認事項** を簡潔に記載。
